# CX-Codex UI/UX 审计（2026-08-08）

## 结论

CX-Codex 已形成适合本地开发工具的克制界面：主任务清楚、桌面与移动端结构一致、错误恢复入口直接，未出现大面积渐变、装饰性卡片或冗余状态文案。本轮已修复小号辅助文字的 WCAG AA 对比度缺口、真实线程冷启动的重复读取、主阅读区 landmark，以及桌面会话导航和宽度拖柄的屏幕阅读器命名。剩余主题风险是部分旧组件仍使用逐选择器深色覆盖，后续应在触及相关组件时逐步归并到语义 token。

## 发现

### P1（已整改）：主阅读区缺少 `main` landmark

- 位置：`src/App.vue` 的 `#main-content`。
- 证据：修复前独立 Chromium 可访问性树能找到“跳到主要内容”链接和 H1，但首页 landmarks 只有未命名 `aside` 与两个 `header`，没有 `main`；已安装 Codex 桌面端 26.727.6591 的当前 App Shell 则直接使用 `<main data-app-shell-main-surface="default">`。
- 影响：键盘用户仍可用跳转链接进入内容，但依赖 landmark 快捷键的屏幕阅读器用户无法直接定位主阅读区，不满足完整的结构化导航预期。
- 标准：WCAG 1.3.1（信息和关系）、2.4.1（绕过区块）。
- 整改：为既有 `#main-content` 增加唯一的 `role="main"` 和名称“会话内容”，保留 `tabindex="-1"`、跳转链接与移动抽屉关闭后的焦点恢复行为。
- 结果：Headless Playwright 通过角色与可访问名称定位到且仅定位到一个主地标；首个 Tab 仍进入“跳到主要内容”，激活后焦点到达 `#main-content`。

### P2（已整改）：桌面会话导航命名不一致

- 位置：`src/components/layout/DesktopLayout.vue`。
- 证据：修复前移动抽屉具有 `aria-label="会话导航"`，桌面 `aside` 没有可访问名称；宽度拖柄播报英文 “Resize sidebar”，与中文优先界面不一致。
- 影响：屏幕阅读器 landmark 列表无法区分该侧栏职责，中文用户遇到混合语言控件名称。
- 标准：WCAG 1.3.1、2.4.6、3.1.2。
- 整改：桌面 `aside` 与移动抽屉统一命名为“会话导航”，宽度拖柄命名为“调整侧栏宽度”。
- 结果：Headless Playwright 分别通过 complementary 与 button 角色精确定位两个中文名称，首页无重复 ID、无横向溢出或浏览器错误。

### P1（已整改）：小号三级文字未达到 WCAG AA

- 位置：`src/style.css` 的 `--ui-text-tertiary`，以及深色输入框 placeholder 覆盖。
- 证据：`#92928d` 对白色背景为 3.13:1，对侧栏 `#f3f3f2` 为 2.82:1；深色 `zinc-500` 对 `zinc-900` 为 3.67:1、对 `zinc-950` 为 4.12:1。
- 影响：侧栏摘要、时间、空状态、辅助说明和输入占位符在低亮度屏幕及视觉能力下降场景中难以稳定辨认。
- 整改：浅色 secondary/tertiary 调整为 `#5f5f5c` / `#6f6f6c`，深色语义文字调整为 `#f4f4f5` / `#d4d4d8` / `#a1a1aa`；非禁用 placeholder 和辅助说明统一使用语义 token，禁用态继续保持弱化但不承载必要信息。
- 结果：明色全量回归的 25 个真实 DOM 样本最低 4.54，深色 26 个样本最低 5.68；独立 Chromium 四组复核得到相同桌面最低值。

### P2：深色主题仍依赖大量逐选择器覆盖

- 位置：`src/style.css` 的 `:root.dark ...` 规则。
- 影响：同一语义文字可能分别来自 `--ui-text-tertiary`、`text-zinc-400` 或 `text-zinc-500`，后续新增组件容易产生主题不一致。
- 建议：先补齐深色语义文字 token，并优先让新组件使用 token；不在本轮做全量样式重写。

### P2（已整改）：真实线程冷启动曾出现重复早期读取

- 位置：`src/App.vue` 的线程路由初始化顺序，以及 `src/composables/useDesktopState.ts` 的目标读取时机。
- 证据：旧顺序在首次选择完成前放行路由 watcher，650 ms 内可观察到两次早期 `thread/read`。
- 影响：弱网下增加首屏竞争，并使非核心“持续目标”读取占用首屏请求窗口。
- 整改：首次线程选择完成后再放行 watcher；非核心目标读取延后 900 ms；RPC 门禁按方法记录并只统计 `thread/read`。
- 结果：聚焦真实线程回归在 650 ms 窗口内只发生一次早期 `thread/read`；缓存首屏 162 ms，前台恢复 P95 100 ms。

## 整改验证

- 当前生产构建的明色和深色全量 7420 回归各通过 38 个界面，1602 条消息场景分别为 13 个挂载节点、62/60 ms 最大心跳延迟。
- Headless Playwright 在浅色/深色、1440 x 900/393 x 852 四种组合下均无横向溢出、非 favicon 控制台错误或页面错误；截图保存在 `output/regression-7420/steady-goal-playwright-20260808`。
- 已人工检查明色桌面、深色桌面和深色手机截图；信息层级、主操作可达性和响应式布局符合本地任务控制层定位。
- Windows Chromium 通过 CDP 把 `forced-colors` 设为 `active`、`prefers-contrast` 设为 `more`；会话夹具中的按钮边界、状态文案和键盘焦点仍可辨认，首个 Tab 焦点具有系统高对比度轮廓。截图为 `output/a11y-forced-colors-focus-before-20260808.png`。这是浏览器强制颜色证据，不替代真实 Windows 高对比度系统切换。
- 首页可访问性探针检查 22 个可见交互控件，未发现无名称控件或重复 ID；会话夹具检查 23 个可见交互控件，同样未发现无名称控件或重复 ID。
- 语义整改后的独立 Headless Playwright 在生产构建上验证唯一命名主地标、命名桌面导航、中文宽度拖柄、跳转链接焦点转移和强制颜色键盘轮廓；无重复 ID、横向溢出、页面错误或控制台错误。截图为 `output/a11y-landmarks-forced-colors-after-20260808.png`。

## 已验证优势

- 手机弹层具备前后 Tab 环绕、外部焦点回收、关闭后焦点恢复和 body 滚动恢复。
- 桌面输入框 Enter 发送，手机 Enter 换行且 Ctrl/Command + Enter 发送；IME 组合输入不会误提交。
- 加载失败提供“重试”和“切换地址”，文案短且操作可恢复。
- 长消息、图片手势、线程切换滚动锚点、前台恢复锚点均有浏览器回归覆盖。
- UI 保持中文优先、低噪声和任务导向，符合本地 Codex 控制层而非通用 IDE 的定位。

## 本轮边界

- 不做视觉重设计、组件库迁移或暗色样式全量重写。
- 不把禁用态颜色当作正文对比度问题处理。
- Windows 高对比度、屏幕阅读器实测和 Android 真机仍需独立设备证据，不能由桌面浏览器截图替代。
- 当前强制颜色仿真只证明浏览器 CSS/DOM 响应，不等同于用户桌面开启 Windows 高对比度后的完整系统实测；真实屏幕阅读器朗读顺序也仍需独立证据。
