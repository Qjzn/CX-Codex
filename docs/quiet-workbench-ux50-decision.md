# UX-50 Artifact Inspector 准入决定

日期：2026-08-29
结论：No-go，本轮不建设右侧 Artifact Inspector。

## 判断

PRD 要求四项准入标准全部满足。当前证据只证明 CX-Codex 已有文件卡、命令输出、Markdown/diff、计划、raw payload 与图片预览能够通过 inline 或 modal 按需查看；没有用户任务数据证明至少两个高频审阅场景被现有路径明显打断，也没有完成能证明右栏减少一次以上上下文切换的对照原型。因此准入标准 1、2 未满足。

在这种情况下实现右栏会增加桌面布局、焦点恢复、阅读锚点、compact overlay 和 Android Back 的验证面，却没有已证实的核心任务收益。Sema 的三栏形态只作为密度参考，不构成 CX-Codex 的需求证据。

## 本轮处理

- 保留现有 inline 命令/过程详情、结构化卡和图片 modal。
- 继续通过 UX-30 的单一过程摘要降低第一层噪声。
- 1024px 以下不增加固定详情栏，不改变正文宽度和移动返回顺序。
- 不新增文件状态、Runtime 状态、权限或持久化所有权。

## 重新评估触发条件

只有同时收集到以下证据才重开 UX-50：

1. 至少两个高频任务的现有 inline/modal 路径出现可复现的阅读中断。
2. 同任务原型对比证明右栏至少减少一次上下文切换，并改善完成时间或错误率。
3. 桌面、compact overlay 和手机 sheet 的焦点/返回/滚动锚点原型通过。
4. 实现仍保持只读且不增加 Runtime、权限或持久化所有权。
