## 1. 摘要

把会话首页从“后台事件查看器”调整为“远程对话与任务接续工具”：发送立即有回声，处理状态可信可见，进展文字自动出现，最终结果优先，技术细节主动展开。手机与桌面共用同一套清晰默认体验，不再让用户先理解队列、RPC和工具事件才能判断任务是否工作。

1.1先完成方案审查，随后按用户“进行下一步”启动P0发送确认及队列安全切片；本轮不重启或替换7420，不提交或发布。本方案按用户最新要求调整展示优先级；保留已有单一会话投影、权威执行状态、幂等发送、权限、恢复与发布门禁。详细操作用例见[验收场景](QA-CX-Codex-Conversation-Experience.md)，候选证据见[测试记录](../tests.md)。

## 3. 背景与已核实问题

### 用户要完成的事

发出需求，确认系统接到了、确实在处理，读懂中间发现和最终结论；只有不放心或需要排障时，才查看执行细节。用户不是为了远程阅读终端而打开手机。

### 证据边界

- 用户反馈“队列→正文失败→后来成功”。本轮没有复现这一现场，不能将某一代码分支宣称为本次故障的确定根因。上一轮正常发送单样本和核心回归通过，也不能关闭这条异常视觉路径。
- 队列确实拥有独立的展示位置，启动后通过`promoteQueuedMessageToOptimistic`转换成正文消息；正文气泡和队列间搬移是当前代码支持的行为。见`src/composables/useDesktopState.ts:8152`。
- 发送策略复用了停止能力：`ThreadComposer.vue:1320`根据`isTurnInProgress`选queue，而`App.vue:890`传入的是`isSelectedThreadInterruptible`。能停止与应排队不是同一个产品判断。
- `ThreadConversation.vue:731`使活动轮次的过程区保持展开，问题并非简单的“默认折叠”。`:749`把进展文字和工具活动混在一起，`:804`默认只保留最后一块，`:1877`又将相关正文压到三行，因此命令或“分析问题”活动能顶替可读文字。
- 动画存在于`ThreadConversation.vue:422`，但在过程、方案、文件和审批之后，且有状态显示条件；计时位于另一个区域。源码存在不等于用户当前视口能看见。
- 文件明细已经默认折叠（`ThreadConversation.vue:313`）；命令本体仍直接显示（`:228`）。不需要重复造文件折叠，应降低它的默认层级。
- 当前`reasoning`只映射为“分析问题”元数据（`src/conversation-transcript/projectConversation.ts:692`）。现成可读过程主要是模型公开的`commentary`，不是一份可直接打开的原始内部推理正文。

### 与旧方案的关系

保留Sema参考带来的结构化turn/item、显式final、稳定身份和可追溯过程；不再把它的工程活动密度当作手机默认阅读体验。实现时须同步修订`DESIGN.md`和旧Quiet Workbench PRD中“混合过程末块”“技术过程自动展开”“文件摘要先于结果”等冲突条款；本方案的“确认无文字回答时显示结束说明”也与`DESIGN.md`、`PRODUCT_GOAL.md`中普通missing final视觉静默的旧规则冲突，实施前须显式更新这一展示门禁，并在目标进度中说明理由。不改安全、权威数据、恢复和正式发布门禁，也不恢复旧扁平助手消息模型。

## 4. 目标与验收指标

以下为拟定验收门槛，不是本轮实测结果；首次实现后校准测试设备与网络条件，不通过降低真实性换取数字。

| 目标 | 验收标准 |
| --- | --- |
| 点击即有反馈 | 前台可交互页面，从有效提交到气泡实际可见P95≤100ms；附件上传时间另计 |
| 状态有依据 | 未确认、超时、请求暂查不到均不显示“发送失败”；有明确拒绝或确定未接收证据才显示失败 |
| 一次发送一条消息 | 同一执行幂等ID不重复启动；同一逻辑消息维持显示身份，编辑/重试规则见7.2.1 |
| 运行一眼可知 | 浏览器接收有效权威开始事件到主状态栏实际可见P95≤100ms，不依赖展开过程或等待第一段文本 |
| 进展及时呈现 | 浏览器接收可展示文本到对应文字实际可见P95≤100ms，不等待工具结束、完整历史读取或打字动画 |
| 后台技术信息不默认展开 | 原始工具卡、命令输出、JSON及diff默认不挂载；模型公开文字可以包含必要的命令引用或代码，不能为达标删除原文 |
| 恢复可信 | 后台返回先保留内容并自动核对；确定完成后不再保留“思考中”；耗时不从0重计 |
| 可读可操作 | 393×852、884×1104和1440×900无横向溢出；粗指针主要按钮≥44px |

计数分别记录首次、已有会话、排队、断网恢复和后台恢复，不混合平均。首段模型等待、Bridge等待、网络等待和前端数据到可见分开记录；不拿本机单样本声称公网P95达标。

### 统一测量口径

| 测量点 | 定义 |
| --- | --- |
| `tSubmit` | 浏览器接受有效提交动作，尚未等待请求返回 |
| `tBubbleVisible` | 匹配显示身份的气泡实际进入可见区域，不是仅写入Vue状态 |
| `tStartReceived` | 浏览器收到并校验当前执行身份/代际的开始事件或等效权威快照 |
| `tRunningVisible` | 匹配当前轮次的主运行栏实际可见 |
| `tTextReceived` | 浏览器收到本次待显示文本的数据；不能挪到Markdown处理结束后才开始计时 |
| `tTextVisible` | 对应item文本实际可见的首次帧 |

三项前端预算分别计算`tBubbleVisible-tSubmit`、`tRunningVisible-tStartReceived`、`tTextVisible-tTextReceived`，统一使用浏览器单调时钟。服务端接收、执行开始及发出事件分别记录服务端时间；没有跨端时钟校准时，禁止直接相减后称为网络耗时。

只有前台、对应内容应当可见且非用户主动阅读历史的样本进入可见性P95。后台、离页、被键盘/遮罩遮挡、恢复快照样本分组标注；应显示却未显示是失败或超时样本，不能丢弃或记为0。30次样本用于初验，不作为长期稳定性的统计证明。

故障用例记录每次可见状态、显示/请求/轮次身份以及启动次数，必须检查完整过程中的错误闪现与重复节点，不能只断言最终成功。

## 5. 用户与使用场景

- 首要用户：用手机远程提出问题、跟进修改、确认结果的人。默认不想看命令及文件diff。
- 次要用户：用桌面继续同一任务、偶尔排查失败的开发者。可以深入查看相同数据，但默认不用另一套复杂布局。
- 必须覆盖：首次发送、连续追问、附带图片、慢响应、确认丢失、切后台两分钟、重新打开页面、计划确认、目标续跑与暂停、权限请求、执行失败。

## 6. 核心价值与取舍

- 看得见回应，而不是看见基础设施：气泡立即出现，但不提前伪造送达或执行成功。
- 看得懂进展，而不是读日志：保留模型公开的发现、判断和下一步说明；工具活动不能覆盖它。
- 安静但不隐瞒：正常恢复不弹窗，真正需要输入、授权、登录或处理失败时明确告知。
- 自动选择低风险默认行为：保留草稿、恢复连接、核对送达、接续已授权队列、保持阅读位置；不替用户批准敏感操作。
- 第一版不增加模型调用来总结每个工具事件，不做额外“状态解释Agent”，不增加重型动效框架或第二套Runtime。

## 7. 方案

### 7.1 唯一默认界面

```text
你：帮我检查发送后为什么会先显示失败。

  已找到发送确认和执行状态共用的判断，
  接下来核对断网恢复时是否把未知状态当作失败。

  查看此前进展                  查看操作详情

  ◌ 正在处理 · 00:18                         停止
  [继续输入……]                               发送
```

示例文字仅为版式说明，产品不能用这类固定话术冒充模型实际输出。

三个层次各司其职：

1. 默认层：用户消息、单一运行栏、公开进展文字、最终结果。手机和桌面一致。
2. 进展历史：展开后只读文字过程，不混入命令和日志。
3. 操作详情：命令、输出、检索、MCP、协作、文件明细等；按实际顺序分组、懒加载。权限问题不埋在这里。

当前会话只有一个主运行栏：放在Composer上缘的独立布局行、会话滚动区之外，与输入区共用宽度。它不能随长进展滚出屏幕，也不能作为覆盖正文的悬浮层；状态只读当前权威投影，不恢复旧尾部推断逻辑。其他历史轮次只保留静态耗时及展开入口，不重复显示活动动画。

手机键盘、安全区和横竖屏改变时，Composer及主运行栏一起位于可视区内；长状态允许摘要换行，停止等主要操作仍保留≥44px触控区。若可用高度不足，优先压缩输入区的非必要选项，不用第二个浮动状态栏补救。终态用一行紧凑结果状态替换活动栏，避免突然移除布局行；下一次有效提交再原位切换。

用户读历史时不强制拉回底部。回到最新入口只负责定位及提示有新内容，不另开一套思考动画。具体阅读保护见7.4.1。

### 7.2 消息始终在对话里

有效提交后，立即以稳定的逻辑显示身份呈现用户气泡。暂存正文、附件身份及发送关联由现有outbox负责；收到服务端身份后原位确认，不删除后重插，不通过短暂红色失败过渡。显示身份和执行幂等ID的职责必须分开，规则见7.2.1。

| 已知事实 | 用户看到 | 系统行为 |
| --- | --- | --- |
| 本地已接受，网络请求尚未确认 | 气泡立即显示，细小待确认标记；等待较明显时显示“正在发送” | 复用原请求身份与durable outbox |
| 服务端接受，尚未开始执行 | “已收到，准备处理” | 等待权威开始事件，不假装正在思考 |
| 当前任务确实在执行，新消息已入队 | 同一气泡显示“将在本次回复后处理” | 自动顺序接续；提供编辑/取消，更多里提供顺序调整 |
| 请求超时、确认丢失或查不到 | “正在确认是否送达” | 查询已有请求、通知、回放和快照；不直接红色报错，不盲目再发turn/start |
| 断网且没有确认送达 | “等待网络恢复” | 保留草稿与气泡；恢复后先核对再决定是否安全发送 |
| 服务明确拒绝或已证明未接收 | 气泡旁“未发送”，说明和重试入口 | 保留内容；按7.2.1区分同请求网络重放和明确重试，不复用已终结请求假装重新执行 |
| 消息已收到，但任务后来执行失败 | 气泡保持已送达；回复区显示“本次处理未完成” | 不把执行失败改写成发送失败 |

首次发消息不应因为创建会话或“可停止”标记进入业务队列。队列只由实际调度事实决定，不由加载、按钮能力或动画状态推断。输入区不再重复完整队列卡片；确需入口时仅显示待处理数量并定位到对应气泡。现有编辑、取消、重排、失败首项保护不能因此丢失。

发生不可取消的在途请求时，取消按钮不得假装成功；显示“正在确认取消结果”，由权威结果决定。晚到的接受/完成证据必须收敛，不固守错误的本地失败判断；必要时一次性内联说明“已恢复送达”，不连发toast。

自动恢复必须有次数、退避和总时长上限，优先复用现有恢复预算。超过预算仍无证据时，明确显示“暂时无法确认送达”，提供重新检查与复制内容，不无限显示正在确认，也不自动重发可能已执行的任务。已有outbox容量、保留期和清理边界继续生效；本地保存失败时保留输入内容并说明，不能清空输入后假装已接收。

### 7.2.1 消息身份与编辑／重试契约

以下名称描述职责，实现优先复用已有字段，不要求再建独立数据库或助手消息缓存：

| 身份 | 用途 | 何时变化 |
| --- | --- | --- |
| `displayMessageId` | 一个逻辑用户消息的展示键，关联草稿版本、outbox与权威用户item | 确认是另一次独立发送才新建；同消息送达核对和安全重试保持 |
| `clientMessageId` | 一次不可变执行请求的幂等键，绑定目标线程、内容、附件及提交选项 | 内容/提交意图修订或确认旧尝试已终结后的新执行尝试使用新键；网络重放不变 |
| `requestId / turnId / itemId` | 服务端接受、执行与历史身份 | 由权威服务提供，不能用最后一条相似文字推断关联 |

- 尚未向服务提交的本地待发消息可以原位编辑；用新请求身份关联新版本，并原子废弃旧outbox发送资格。原显示键不变。
- 已在服务端排队的消息编辑时先保留B为草稿版本，原气泡仍是已接受的A；仅在权威确认A已取消且不会开始后，才能提交B并原位更新显示版本。不能把“取消请求已发出”当作取消成功。
- 取消确认丢失或请求暂时404时，B不提交、不自动重复取消后重发；显示“正在确认修改结果”，按现有有界恢复核对。
- 如果A先开始，保留A的真实正文和执行结果；B回到可编辑草稿，提示“原消息已开始处理，修改内容尚未发送”。不自动把B追加为另一轮。B后来经用户明确发送才是新逻辑消息。
- 同一不可变请求的网络重放复用`clientMessageId`。明确未开始且旧尝试已不可再执行时，用户点击“重试”可创建新执行键、保留显示键；已完成任务的“再执行一次”必须是新逻辑消息。未知结果不能自动升级成新执行键。
- 后端已有同ID不同内容拒绝规则（`src/server/runtimeMessageQueue.ts`），不得为了原位编辑而削弱幂等校验。晚到事件按其实际执行键归属，旧A结果不能挂到B正文下面。
- 身份映射放进现有有界用户送达元数据，保留现有清理与TTL；不得复制助手内容或无限留存。浏览器重载后要求逻辑关联一致，不要求物理DOM对象相同；同页仍挂载的气泡则不能因确认/身份绑定重建节点。虚拟化正常离屏卸载不算身份丢失。
- 若现有API不能提供安全取消/确认，禁用已接受消息的原位编辑并解释原因，保留草稿；不能先开放按钮再依靠概率避免双执行。

2026-09-10候选落实此降级分支：当前队列没有“从未提交”的可靠事实，连本地failed也可能是ACK丢失。因此全部已进入队列链路的行都暂不开放原位编辑；“立即引用”存在同样的先取消再创建新请求风险，一并保护。正文只读但可全文阅读和选择，内联解释原因，原队列与草稿保留。该保护不证明底层取消成功，也不影响独立未发送托盘的编辑流程；取得可验证的安全取消契约后才能重新开放这两个入口。

2026-09-10原生身份候选：投影的`displayMessageId`和轮次`renderKey`与真实`itemId/turnId`分离。发送将现有不可变`clientMessageId`传为原生`clientUserMessageId`；快照和通知优先读取用户`clientId`，兼容旧别名。同页确认原位更新；精确映射先进入现有有界用户缓存再清理outbox。真实协议中live UUID可能在历史读取时变为`item-1`，只按同轮、跨来源、一对一原生身份归并；同来源多项或跨轮冲突不猜配。重载保留逻辑身份，不承诺跨document保留物理DOM。

撤回上一候选的`openerTurnId`推断：新版`turn/start`也能接续活动轮次，返回轮次不能证明快照的第一条用户消息属于本请求。移除该自定义字段的生成、顶层暴露和前端解释，不迁移或清理用户数据库。普通turnId、正文、时间相近均不是现代请求的确认依据。只有运行状态先到、仍无对应消息或轮次事件时，不凭状态轮询在未绑定本地气泡旁创造空轮次；保留“确认中”，不伪装为已执行。

当前CLI 0.153.4已通过真实app-server与回环假模型验证：原生字段在通知、快照、重启后resume/read中保留。模型请求仅落到本地固定响应，无真实账号、工具或外部网络请求；不等于真实模型性能、7420或手机通过。配套Web/CLI代码仍是本地候选。日志回退现保留`event_msg.payload.client_id`及增量缓存身份，只在明确且无冲突的任务生命周期下绑定轮次；不把相同正文或相邻response记录当作精确关联。

同轮双来源显示按官方0.153.4的UI历史职责选择：有日志用户事件或原生snapshot/notification用户项时，模型输入`response_item`不再冒充第二条用户气泡；不回填client、不伪造逐条alias。同轮所有投影用户消息保持独立显示键和可见正文，仅首条提供轮次回退。

原生raw先到的候选补充：从实际文件头确认首个完整非空`session_meta`的ID匹配且显式`history_mode=legacy`后，读取入口从首帧排除普通模型输入用户，等待UI事件自身的身份；完整或可信增量的空历史返回可用快照，不转入慢速完整RPC。截断冷尾窗不冒认完整空历史，读取中来源变化的结果不得进入外层缓存；私有缓存保留隐藏轮次边界，避免后续答复挂到上一轮。头探测最多64KiB且独立于尾窗；完整头指纹、文件身份和线程ID共同保护缓存。原文件不改。缺失/未知/不完整/超预算头继续旧格式兼容，不能用正文或CLI版本猜测确认；这是CX的保守边界，不等同于原生缺失模式默认值或未知模式拒绝行为。新版paginated日志、未知格式raw-only、新任务预览交接、跨父轮次搬移及完整CX-CE-02仍需独立验收。最新自动化和浏览器正反例见`tests.md`。

### 7.3 稳定运行栏：状态、动画、时间放在一起

默认使用“正在处理”，而不是把整个工具执行时长都说成纯模型“思考时间”。明确处于可识别的模型阶段时可显示“正在思考”，但秒数仍标注处理用时。

- 运行：轻量动画＋“正在处理 · 00:18”，停止入口保持可达；不逐个切换“读取文件/运行命令/分析问题”。
- 等待确认：显示“需要你的确认”，将具体问题放在阅读区末尾、主运行栏之前，处理计时暂停，动画停止；用户在读历史时提供“查看问题”定位按钮，不抢焦点。
- 停止请求尚未确认：显示“正在停止”，不能提前显示“已停止”。
- 连接中断：显示“连接已断开，正在恢复状态”，保留文字；不以持续思考动画保证服务仍在执行。
- 连接存在但执行事实不够新：显示“正在更新状态”，详情保留上次确认时间；没有新文字本身不等于卡死或断网。
- 完成/失败/中断：权威终态立即停止运行效果，不为了动画最短时长延迟结果。

耗时复用权威开始、结束与等待区间。展示层可使用独立1秒时钟，只更新可见活动栏，不触发RPC、持久写入或整段会话重投影。后台暂停本地绘制；返回按时间锚点恢复，不累计后台timer次数。缺少权威开始时间就暂不显示秒数，不伪造00:00起跑；处理用时、等待用户用时和传输等待不能相互冒充。

### 7.3.1 组合状态与优先级

先按线程、执行键、turn及现有代际/事件顺序匹配事实，再选择展示；下面的优先级不能用于跨轮覆盖。后续排队消息的状态属于其气泡，不能盖住当前正在执行的轮次。若同代际权威事实仍冲突，进入“正在核对状态”，保留已知内容，禁止自动审批/重发。

同一请求/轮次按“已确认终态 → 未解决的权威交互 → 停止结果待确认 → 执行证据及其新鲜度 → 已接受/排队 → 本地发送”决定主状态；已确认接受/执行证据优先于该请求的本地送达错误。目标与连接是附加事实，不能自行改写turn状态。

| 组合事实 | 主展示／附加说明 | 动画与计时 | 可用操作 |
| --- | --- | --- | --- |
| 已确认完成＋断网或旧running到达 | 已完成；连接提示只影响后续联网操作 | 无活动动画，冻结权威用时 | 复制已有结果；联网动作待恢复 |
| 部分final＋权威失败/中断 | 处理未完成/已中断；保留部分回答及失败说明 | 无活动动画，冻结权威用时 | 查看详情；仅按安全条件重试 |
| 未解决审批/问题＋连接正常 | 需要你的确认 | 无运行效果，处理用时暂停；等待时间另计 | 现有合法回答/批准/拒绝动作 |
| 上次状态是等待确认＋断网 | 需要确认（上次状态）；连接恢复后核对 | 不继续累计处理用时，不显示思考动画 | 只读查看问题；恢复并确认有效后才可提交 |
| 停止请求已发＋尚无终态/确认 | 正在确认停止结果 | 不展示已停止；时间仅显示已确认部分，标注核对中 | 查看状态；不启动替代任务 |
| 已确认当前轮执行＋发送ACK丢失 | 正在处理；该消息送达状态已确认 | 权威时间锚点计时、运行效果 | 停止（依现有能力），查看进展 |
| 当前轮running＋目标paused | 正在处理；后续目标已暂停 | 当前轮继续正常计时与动画 | 可停止当前轮；不得自动续跑目标 |
| 执行状态缺乏新鲜证据＋重连中 | 正在恢复状态；上次确认状态作为次级说明 | 不以思考动画保证仍在执行；显示截至上次确认的用时 | 自动核对、查看已有内容，不盲目重发 |
| 仅确认服务已接受，尚无开始证据 | 已收到，准备处理；若实际排队则显示等候说明 | 不开始执行计时或思考动画 | 按现有能力取消/编辑，不猜执行开始 |
| 无接受证据且明确拒绝 | 未发送＋可理解原因 | 无运行效果/执行计时 | 保留内容，修正后按身份契约重试 |

状态新鲜度来自现有Runtime/线程权威状态与连接恢复机制，不能用“多久没出文字”判断。P0须将使用的超时、恢复总预算、确认间隔及来源列为测试配置；若找不到相应权威字段或预算映射，记录能力缺口，不能在组件里各猜一组阈值。终态和需要用户处理的事实不做防抖延迟；正常进度文案可以合并同帧更新，但不得省掉真实异常或把相矛盾状态闪现一遍后再修正。

### 7.4 默认展示文字，不展示事件

- 第一版直接使用现有明确面向用户的`commentary`。保留原始身份、顺序和文字；结构化命令、文件、通用“分析问题”事件不能替换当前文字。模型原文中的必要命令引用、路径、代码示例可以显示，“后台信息不默认展开”不等于删除原文中的技术词。
- 只有处于跟随最新状态时，默认窗口才保留最近两段公开进展；一旦进入阅读保护，按7.4.1冻结窗口。新的工具事件不减少可见文字，较早文字仍可从“此前进展”访问。最后一段正在流式更新的普通正文不按三行截断，长文本使用页面滚动；主状态栏因位于滚动区外仍可见。
- 用户主动展开历史后不因完成或新事件被收回。若需要限制超长已完成段落，可提供明确的“展开全文”，但不能静默截断含行动要求的文字。
- 无公开文字时只显示可信运行栏，不编造“正在分析需求”等随机步骤，不播放循环打字假过程。
- 未来仅在协议明确支持时接入允许公开的简短推理摘要；不恢复内部原始推理链、系统提示、原始reasoning payload，也不为流式进展额外发总结请求。
- 计划方案、审批问题和最终回答不是进展文字；它们保留各自语义、操作和显式身份。

正文保真规则：禁止正则删除包含`npm test`、终端关键词或路径的整句；短行内代码保持原样。模型公开文字中的已完成代码块超过12行时，可用“展开代码（N行）”按结构折叠，保留完整复制/展开能力；正在流式变化或含当前选区/焦点的代码块不自动折叠。实际工具的命令与stdout仍只在操作详情内出现。此阈值是首版展示参数，须用手机样例校准，不影响数据保留。

### 7.4.1 阅读保护与窗口切换

| 阅读状态 | 触发 | 新进展到达后的行为 |
| --- | --- | --- |
| 跟随最新 | 用户处于底部，未选中文本、未聚焦详情、未展开历史 | 合并流式绘制，允许移动最近两段窗口，保持底部跟随 |
| 阅读保护 | 用户上滑离开底部、选择正文、聚焦内容内交互或展开历史，任一成立 | 冻结当前显示范围的起点和身份；不移除正在读的块、不折叠、不抢焦点、不自动滚动，只提示有新进展 |
| 恢复跟随 | 用户明确点击“回到最新”，或在无选区/详情焦点/手动展开状态下主动滚到底部 | 恢复最新窗口及后续跟随；不因后台布局变化碰巧到达底部就自动解除保护 |

阅读保护是页面呈现状态，不是新的会话事实。新数据仍按协议进入单一投影；允许更新同一item的后续文本，但不能重建选区所在的DOM祖先或把该item移进隐藏历史。用户选中文字或正在操作时，可延后该块的破坏性重渲染，仍持续接收数据并提示有更新；解除保护后补绘。已有锚点/虚拟化能力继续使用，超出挂载预算时按稳定锚点加载，而不是无限追加DOM。

完成事件只更新主状态栏与真实结果，不解除阅读保护。P1放行必须覆盖393×852且键盘打开、两段长文字、第三段到达、选区与焦点不丢失；不能等到后续动效任务才补这条正确性要求。

### 7.5 点击后看操作，但不伪造因果关系

在进展旁放一个清楚的“查看操作详情”按钮，不把整段可复制文字变成点击热区。展开后先给操作摘要，再按需展开命令与输出；长输出有上限、懒加载及原有安全边界。

已有明确关联ID时可显示该进展对应操作；只有时间顺序时命名为“该阶段操作”，不是“这段思考导致的命令”。并行工具、跨进展运行的命令及没有对应进展的操作统一归入本轮详情，保留真实turn/item身份，不凭文本猜关联。

手机默认不挂载命令输出和diff。变更文件作为完成结果之后的次级入口，例如“变更文件 3”；仍可查看/下载模型明确产出的报告或图片，不能把用户真正需要的交付物也藏进技术日志。

### 7.6 最终结果优先，但不提前宣布成功

显式final文本一到就原位流式呈现，不等待旧命令输出补齐、全部历史RPC完成或人为打字效果。是否执行完成仍服从权威turn终态：final已出现但任务仍活动时，运行状态不能被提前删除。

部分final已经出现后发生失败或中断，保留可读回答，但失败/中断说明及可用恢复操作必须独立出现在首层。不能用“有final”覆盖真实执行失败，也不能把部分回答当作业务成功证明。

终态到达后停止动画、冻结权威用时，最终回答成为主阅读区域；默认未展开的过程收敛为“处理过程 · 用时32秒”。用户正在查看的过程不强行收起，保持阅读锚点和焦点。最终答案及交付物不能被后到日志挤走。

执行成功只表示本轮正常结束，不自动等同于业务目标达成。缺少显式final时不把最后一条commentary升格为回答；若有权威完成事实且确认没有回答，用一行“本次处理已结束，未返回文字结果”解释，不留无限思考状态。

### 7.7 自动化的边界

| 默认自动完成 | 仍必须交给用户 |
| --- | --- |
| 草稿保存、连接恢复、事件补齐、核对送达、已授权队列顺序接续 | 权限升级、敏感删除、对外提交/发布、登录或额度处理 |
| 记住现有模型与展示偏好，不每次要求配置 | 显著费用变化、新付费动作、重大模型替换 |
| 现有执行模式下直接处理已授权需求 | 计划模式的“执行此计划”确认，不偷偷切换为执行 |
| 用户停在底部时跟随输出；阅读历史时保持位置 | 不强制打开详情、跳任务、抢焦点或清空未提交内容 |

正常恢复与完成不用模态弹窗。需要回答/授权时优先使用会话内单一卡片，解释“为什么需要你”和下一步；不因每次重放重复创建卡片。真正安全关键的确认不能为了安静而绕过。

持续目标复用同一运行栏，不额外叠一套spinner。目标完成、暂停、预算受限等来自权威目标，只决定目标自身和后续续跑；当前turn执行状态仍独立来自权威turn，尤其目标暂停不等于当前轮已停止。计划任务展示真实下一次时间与最近结果；到点仅表示触发，不提前表示执行成功。本方案不新增自动化任务，也不替代现有目标/调度回归。

### 7.8 动效与可访问性

- 一个活动栏使用一种轻量运行效果；状态文案保持稳定，秒数等宽，不随字数推挤按钮。
- 点击反馈80–120ms，展开/淡入120–180ms，仅小幅opacity/transform；这些是设计预算，不是人为延迟数据的理由。
- 不对整段历史高度做动画，不逐token重建整篇Markdown，不用打字机故意拖慢已收到内容；按帧批量更新并保留安全Markdown渲染。
- 使用`prefers-reduced-motion`时去掉非必要动态效果，但保留文字状态及用时。状态变化使用适当的`role=status`，不抢焦点，不每秒向屏幕阅读器播报时间。
- 上述取舍参考[W3C状态消息说明](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html)与[交互动效说明](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html)。本文件不是可访问性符合性声明。

### 7.9 长期实现边界

不重写后端。保留outbox、队列、Runtime与ConversationProjection的事实所有权；把重复的显示决策收敛为可测试的纯展示选择器，由同一组事实产出主状态、公开文字、详情入口与时间锚点，不维护第二套持久状态机。

发送送达、执行状态和同步新鲜度是三个不同维度。组件不能再分别用“能停止”“是否有文本”“是否加载中”猜同一件事；对同一轮新旧通知按已有代际/身份规则处理，终态不能被旧running复活。

优先复用`ConversationTurn.commentary/activities/fileChanges/interactions/final`，以小型组件隔离运行栏、进展文字和操作详情。仅当内容数量需要时虚拟化/分页；折叠不能只藏CSS却继续挂载完整日志。计时更新不触发全历史解析；后端原生分页与慢RPC观测单独实施，不与本次视觉变更混为一次不可回滚重写。

首版不提供“简洁／高级／旧版”三套长期模式：默认简洁，按需展开详情即可。回滚靠版本与部署备份，不靠运行时恢复旧会话语义。

### 必须新增的回归

1. 首次／已有会话：有效提交后一条气泡；ACK、thread创建、turn开始分别延迟，画面仍正确。
2. 真正在忙时连续发三条：所有消息可见、顺序正确，取消或重排不破坏身份；恢复后一次执行。
3. 服务接受但ACK丢失；恢复查询再失败；返回HTML或截断JSON；请求暂时404；事件比HTTP晚到：均不靠通用catch直接判未发送。
4. 明确参数拒绝、权限拒绝、上传失败、执行失败：原因与恢复入口正确，送达和执行错误不混淆。
5. 公开进展→命令→工具输出→新的公开进展：原文字不被命令顶替，默认没有结构化工具日志；模型原文中的技术引用不被删掉。
6. 没有公开进展的长任务：有真实运行状态与用时，无编造文字和假进度百分比。
7. 打开过程历史后收到final：不强制折叠、不跳视口；默认态用户则优先看最终答案。
8. final先到、turn终态后到；旧running后到：结果即刻可读，完成状态不回退。部分final出现后失败/中断，已有内容保留且错误独立可见。
9. 切后台两分钟，分别在后台完成／仍执行／等待批准／断网：恢复后内容保留、状态收敛、耗时不重置。
10. 计划确认、目标暂停/清除/自动续跑让位队列、调度触发失败及等待授权：默认策略符合真实状态，不能自动批准。
11. 长文本、长日志、长会话、中文输入法、图片加载与键盘打开：无明显掉帧、横向溢出或遮挡。
12. 键盘、屏幕阅读器与减弱动画：展开焦点正确；秒数更新不反复播报，异常通知不重复。

正常路径至少分别采集30次首次/已有会话样本；异常注入每类至少10次，身份与误报断言零失败；性能与压力样本单独报告。真实手机、公网、后台两分钟与长时间浸泡必须单列证据，不能用单元测试或桌面窗口尺寸代替。
